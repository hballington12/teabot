- **WP3.3 plugin purge.** `teabot plugins purge <id>` takes the plugin's advisory lock exclusively, shows what goes, and in one transaction drops the schema and role and the plugin's core rows, queues command syncs and writes audit rows. - **WP3.4 guild removal.** Join and remove events, and a comparison at `on_ready`, keep `core.guilds` current. Removal starts the grace period and queues `purge_guild`; a second removal event changes nothing. A return within the grace period cancels the purge and resumes the jobs, and a command sync sends the commands again, since removal forgets the stored hash. `purge_guild` deletes the server's rows from every plugin schema as that plugin's role, then from every core table with a `guild_id`, its own job row included. That keeps it repeatable, and tables added later are covered without edits. Two design points needed pinning. The startup comparison looks only at this process's shards, or one process of several would mark the others' servers removed. A purge for a server that came back deletes nothing.
